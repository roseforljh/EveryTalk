# EveryTalk 动态提示词与能力卡式编排方案

| 项目 | 内容 |
|---|---|
| 状态 | 核心实现已落地，测试通过 |
| 更新日期 | 2026-07-24 |
| Android 工程 | `app1/` |
| 适用范围 | 普通文字聊天 |
| 排除范围 | 语音、图片生成 |
| 核心原则 | 能力卡提供结构化知识，模型自主选择，应用负责边界校验和执行 |

## 1. 设计目标

EveryTalk 需要根据用户任务调整回答契约，同时避免把所有任务都塞进同一组超长规则。方案需要满足以下条件：

- 模型能看到当前可用的回答能力，并根据用户目标选择组合。
- 应用不根据财报、表格、代码等关键词猜测用户意图。
- 能力选择结果只能引用已注册能力，不能新增工具权限或读取任意本地资源。
- 能力选择失败时仍能正常回答，不阻塞普通聊天。
- 能力卡、稳定 system 和工具 schema 可形成稳定缓存族。
- Markdown 输出在渲染前具备最小结构校验，避免模型把正文和表头粘在同一行。

## 2. 最终架构

```text
稳定 system 提示词
    ├── 核心回答规则
    ├── 能力卡目录摘要
    └── everytalk_select_capabilities 选择协议
             │
             ▼
模型阅读用户问题并自主选择能力卡
             │
             ▼
everytalk_select_capabilities
             │
             ├── ID 校验
             ├── 任务卡数量校验
             ├── 选择数量校验
             └── 返回受控能力指令正文
             │
             ▼
模型生成最终回答
             │
             ▼
MarkdownContractValidator
             │
             ▼
MikePenz Markdown / EveryTalk 公式和代码渲染链
```

这是一套能力卡式编排机制。能力卡是应用内受控的回答契约集合，不引入可运行的插件系统，也不让能力卡自行获得外部工具权限。

## 3. 能力卡模型

能力卡包含以下字段：

- `id`：稳定的机器可读 ID。
- `kind`：`TASK`、`FORMAT` 或 `SAFETY`。
- 中文摘要和英文摘要：供模型理解能力边界。
- 中文指令和英文指令：选择成功后返回给模型。

首批内置能力卡：

| ID | 类型 | 用途 |
|---|---|---|
| `general-answer` | TASK | 普通问答和事实解释 |
| `explanation-tutoring` | TASK | 概念解释和教学 |
| `coding` | TASK | 代码、配置和实现 |
| `debugging` | TASK | 报错、崩溃、日志和性能排查 |
| `document-analysis` | TASK | PDF、报告、合同和长文档 |
| `data-analysis` | TASK | 数据、指标、统计和趋势 |
| `research` | TASK | 最新信息、网页和外部研究 |
| `writing-editing` | TASK | 写作、润色、改写和翻译 |
| `markdown-table` | FORMAT | 合法 GFM 表格输出 |
| `structured-output` | FORMAT | 报告、摘要和固定字段 |
| `source-citations` | FORMAT | 来源、日期和证据对应 |
| `financial-caution` | SAFETY | 财务、投资和非官方材料风险 |
| `privacy-safety` | SAFETY | 隐私、凭据和敏感信息 |

模型每次选择一个任务卡，并按需要选择格式卡和安全卡。只选择格式卡时，应用自动补充 `general-answer` 作为安全默认任务，不根据关键词推断其他任务。

## 4. 模型选择协议

工具名：`everytalk_select_capabilities`。

参数：

```json
{
  "capabilities": [
    "document-analysis",
    "markdown-table",
    "financial-caution"
  ],
  "language": "zh"
}
```

应用执行以下校验：

1. 选择数量必须在 1 到 5 之间。
2. 每个 ID 必须存在于内置目录。
3. TASK 类型最多一个。
4. 能力卡只能返回目录中已经写入的指令正文。
5. 选择结果不改变工具集合、附件访问范围、系统提示词和外部操作权限。

选择失败时返回结构化错误，模型可以重新调用工具。工具不可用时，稳定 system 仍然提供通用回答规则，模型继续回答，应用不启用关键词分类器作为替代路由。

## 5. 稳定 system 设计

`SystemPromptInjector` 只构建稳定 system 前缀，内容包括：

- 核心回答和安全规则。
- 能力卡目录摘要。
- 能力选择工具协议。
- Markdown、公式和代码块的基础契约。
- 用户自定义 system 提示词。

稳定 system 不包含当前用户原文、当前时间、动态关键词评分结果或 ETD 选择码。已有自定义 system 会合并到稳定提示词末尾，重复注入保持幂等。

## 6. 提供商边界

### OpenAI Chat Completions

能力选择工具和已有工具走同一工具循环。`everytalk_select_capabilities` 由应用本地执行，结果作为工具消息返回模型。

### OpenAI Responses

能力选择工具使用 Responses function calling 格式，复用现有工具循环和缓存字段门控。

### Gemini

能力选择工具转换为 Gemini `functionDeclarations`，执行结果通过现有 function response 循环返回。

### OpenAI Compatible

普通文字聊天加入能力选择工具。

### 语音和图片生成

不注入本地能力卡选择工具，继续使用原有专用链路。

## 7. 财务表格问题修复

问题输入的关键结构是：

```text
特征：| 财务指标 | 2024 财年 | 2025 财年 | 年同比变化 |
| :--- | :--- | :--- | :--- |
```

表头前存在正文字符，Markdown 解析器会把这一行当普通段落，后续分隔行无法组成表格。

`MarkdownContractValidator` 在渲染入口执行最小修复：

- 仅处理代码围栏之外的文本。
- 仅当当前行包含正文前缀、后半行是完整表格行、下一行确实是分隔行时拆分。
- 只增加正文和表头之间的空行，不改写单元格内容。
- 其他无法确定的结构保持原文，避免误伤普通正文和代码。

修复后的结构为：

```markdown
特征：

| 财务指标 | 2024 财年 | 2025 财年 | 年同比变化 |
| :--- | :--- | :--- | :--- |
```

## 8. 缓存策略

- system 变化由 `CAPABILITY_PROTOCOL_VERSION` 控制缓存族版本。
- 工具 schema 使用规范化 JSON 和稳定排序计算 hash。
- OpenAI 官方端点使用稳定的 `prompt_cache_key`。
- 能力选择结果属于当前工具循环上下文，不写入 UI 用户原文。
- 用户历史只保留真实用户和助手消息，不重放本地关键词选择码。
- 工具集合、能力协议或稳定 system 变化时进入新的缓存族。

## 10. 验收标准

- 普通请求不再通过本地关键词选择任务。
- 模型可以从能力卡目录选择任务、格式和安全卡。
- 未注册能力和冲突任务会被应用拒绝。
- 选择结果不能新增工具权限。
- OpenAI Chat、OpenAI Responses 和 Gemini 均复用现有工具循环。
- 财务文本中正文粘连表头时可以渲染为 GFM 表格。
- 代码围栏中的表格样式文本保持原样。
- 稳定 system 注入幂等，用户历史不包含 ETD 选择码。
- 相关定向单测、`compileDebugKotlin` 和 Debug 构建通过。
