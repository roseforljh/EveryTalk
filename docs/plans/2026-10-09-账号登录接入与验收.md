# EveryTalk 账号登录接入与验收

本次只接入 Google 和邮箱验证码登录。首次验证成功后完成注册，已有用户直接登录；原有自带 API 模式无需登录。套餐、支付、额度和聊天同步不在本次范围内。

## 1. 创建 Supabase 项目与客户端配置

1. 在 [Supabase Dashboard](https://supabase.com/dashboard) 创建项目，保存数据库密码到自己的密码管理器。
2. 在项目连接信息或 API Keys 设置中找到项目根地址和 **publishable key**（旧版 **anon key** 也支持）。
3. 在本机 `app1/local.properties` 添加以下公开配置，CI 可使用同名环境变量或 Gradle `-P` 参数：

```properties
SUPABASE_URL=https://你的项目标识.supabase.co
SUPABASE_PUBLISHABLE_KEY=sb_publishable_你的公开客户端Key
```

**service_role、sb_secret_ 和 Google Client Secret 不得进入 APK、Git 或聊天。** 构建脚本会在生成 BuildConfig 前拒绝管理员 Key，App 再次检查公开 Key。认证接口直接使用现有 Ktor，没有增加 Android 依赖。

## 2. 邮箱验证码

1. 在 Authentication 的 Sign In / Providers 中开启 Email，并允许新用户注册。
2. 将 Email OTP 长度设为 **6 位**；建议过期时间设为 10 分钟，保留每邮箱至少 60 秒的重发限制。
3. 先配置自定义 SMTP，完成发件域名验证，使用自己的邮件发送服务。需要 SMTP 主机、端口、用户名、密码、发件邮箱和发件人名称；密码仅填写在 Supabase 后台。默认邮件发送服务只向组织团队成员邮箱发送，有低发送额度，不能作为公开运营的邮件服务。
4. 再在 Email Templates 的 Magic Link 模板中输出 `{{ .Token }}`，不是只有链接。确认新用户所用的 Confirm signup 模板也包含验证码。**2026 年 6 月 3 日起新建的 Free 项目，使用默认 SMTP 时不能自定义认证邮件模板；配置自定义 SMTP 后才可修改。** 因此必须先完成第 3 步。

```html
<h2>EveryTalk 登录验证码</h2>
<p>你的验证码是：{{ .Token }}</p>
<p>请在有效期内填写；如果不是你发起的登录，请忽略这封邮件。</p>
```

5. 在 Auth 的 Rate Limits 中核实验证码验证的尝试限制和邮件发送限制。刚启用自定义 SMTP 仍有较低的默认发送额度，需结合邮件服务额度设置。App 的倒计时只是提示，真正限制由认证服务执行。公开运营前核实验证码滥用防护。

配置依据：[自定义 SMTP 文档](https://supabase.com/docs/guides/auth/auth-smtp)和[新 Free 项目邮件模板限制公告](https://supabase.com/changelog/46599-changes-to-email-template-customisation-on-free-tier)。

接口为 `POST /auth/v1/otp`（`create_user: true`）和 `POST /auth/v1/verify`（`type: email`）。发送成功不建立本地会话；验证成功才显示账号。

## 3. Google 登录

1. 在 Google Cloud 创建 **Web application** OAuth Client，配置品牌、支持邮箱和应用隐私政策。
2. 在 Google 的 Authorized redirect URIs 中填入 **Supabase Google Provider 页面显示的回调地址**，通常是 `https://项目标识.supabase.co/auth/v1/callback`；它不是 App 自定义协议地址。
3. 在 Supabase 的 Google Provider 设置中填写 Client ID / Client Secret 并启用。Secret 只保存在服务端。
4. 在 Supabase 的 URL Configuration → Redirect URLs 中分别添加：

```text
everytalk://oauth/account**
everytalk-debug://oauth/account**
```

只对这两个精确路径允许尾部通配，以容纳随机 `login_state` 参数；不要允许整个协议或所有 HTTPS 域名。按当前 Dashboard 的地址匹配规则核实这两项能覆盖查询参数。

5. Google OAuth 处于测试状态时，将实际测试账号加入测试用户；对外发布前完成适用的发布与审核要求。

App 通过系统浏览器启动 `/auth/v1/authorize`，只请求 `openid email profile`。认证层加密保存随机标识和 PKCE verifier，核验回调地址、标识及 10 分钟有效期，然后用授权码交换会话。回调不接收 access/refresh token。取消、重复或 Debug/Release 混用的回调不会登录成功。

## 4. 查看与管理注册账号

本阶段使用 Supabase Dashboard → Authentication → Users，不开发独立管理员网站。可以查看用户 ID、邮箱、创建时间、最近登录时间和关联身份；删除及封禁等能力以当前 Dashboard 或管理员 API 支持为准。发送新邮箱验证码时，服务端可能已创建待验证用户记录；必须区分待验证账号与真正完成验证的账号，不能把列表人数直接当成已登录人数。

管理员 API 只能在可信后端或受控运维环境使用，不能将管理员密钥放进客户端。Google 与邮箱是否自动归并由 Supabase 的已验证身份关联规则决定，不在 App 中仅按邮箱字符串手工合并。试运行时测试同一个已验证邮箱的两种登录方式是否得到相同用户 ID。

卸载和退出不会删除服务端账号。公开上线前建立私密、可验证身份的账号删除申请渠道，并按分发渠道的要求提供删除入口；不要要求用户在公开 Issue 中发布邮箱、验证码或其他凭据。删除账号由管理员确认后在 Dashboard 执行。

PowerShell 中进入 `app1/`，使用支持当前 Gradle 的 Android Studio JBR 运行（本机为 `C:/Program Files/Android/Android Studio/jbr`）：

```powershell
& 'C:/Program Files/Android/Android Studio/jbr/bin/java.exe' -classpath gradle/wrapper/gradle-wrapper.jar org.gradle.wrapper.GradleWrapperMain :app:testDebugUnitTest --tests 'com.android.everytalk.data.account.AccountAuthTest' --console=plain
```

测试使用 Ktor MockEngine 和内存存储，不连接真实账号，覆盖公开 Key 校验、邮箱注册/登录、重发冷却、错误验证码、PKCE、错误及重复回调、过期授权、会话刷新、撤销与退出。

## 6. 真实环境验收

1. 在设置页右上角三点菜单选择「账户」；未配置时明确显示暂未开放，原有功能仍可使用。
2. 用新邮箱获取验证码：邮箱收到验证码，验证前不显示已登录，验证后 Dashboard 出现账号。
3. 同一邮箱再次登录：用户 ID 不变；错码、过期码不能登录，短时间不能重复发邮件。
4. Google 浏览器授权成功后回到正确 App 变体的账户页；取消后可以取消本次授权并重试。
5. 浏览器授权期间回收 App 进程后，再次打开回调仍可使用加密保存的草稿完成登录；超过 10 分钟需重试。
6. 重新启动 App 后联网核验账户；Token 临近过期时自动刷新。网络临时失败不删除凭据，服务端确认失效后要求重新登录。
7. 退出后重启仍为未登录，聊天记录和自带 API 配置保留。
8. 检查管理后台中的身份、最近登录记录和账号删除操作；核对同邮箱的身份关联行为。
