## 一、最终产品定义

EveryTalk 的 Agent 任务由两部分组成：

1. VPS 保存真正的命令、进程、状态和结果。
2. Android 前台服务负责保持 SSH 连接、接收进度、恢复监听、驱动通知和续接 AgentRun。

用户离开当前会话不会结束任务。只有用户在输入框主动点击“停止”，才会取消当前 AgentRun 创建的全部远端任务。

## 二、必须记住的核心规则

### 2.1 任务持续执行

- 进入其他页面、退出当前会话、退出 App、切换 App、息屏，都不取消 VPS 任务。
- 后台任务没有 10 分钟或 60 分钟硬上限。
- 任务持续到完成、失败、用户取消，或 VPS 上的进程被外部终止。
- 连接断开只影响手机接收，VPS 任务继续运行。

### 2.2 连接方式

- 每台 VPS 使用一条 SSH Transport。
- 一条 Transport 内可以打开多个独立 Channel。
- 同一台 VPS 的多个任务共用 Transport，任务之间使用独立 Channel。
- Transport 断开后，所有任务按各自的 `execution_id` 从 VPS 状态文件重新接管。
- 不为每一条命令重复建立完整 SSH 连接。

### 2.3 实时进度

- 前台会话使用长 SSH Channel 接收进度事件和最终结果。
- Android 前台服务在 App 离开页面后继续保持监听。
- 前台 UI 可以显示新增进度。
- 后台服务把进度按约 200～500 毫秒合并后写入本地状态，避免每一行输出触发一次界面更新。
- 通知只显示状态摘要，不显示完整 stdout、stderr、命令、路径、密钥或环境变量。
- 完整日志保存在 VPS。本地执行记录只保存安全摘要、日志字节游标和最近事件时间，不复制整份敏感日志。
- 发送给 AI 前继续执行现有 Secret、Token、密码和私钥过滤。
- AI 默认接收阶段摘要和最终结果，需要细节时按 `execution_id` 读取指定日志片段。

### 2.4 AI 续接

- 任务完成后，结果接回原来的 AgentRun。
- 原 AgentRun 继续调用原模型，生成完整的 AI 回复。
- 模型调用失败时保存 VPS 最终结果，不重复执行 VPS 命令，稍后重试模型续写。
- 每个任务只允许一个完成事件和一次结果接回，使用 `execution_id` 做幂等控制。
- 原 AgentRun 开始时保存模型和参数快照。任务续接使用快照，新消息使用当前模型配置。

## 三、Android 生命周期规则

### 3.1 App 在前台

| 场景 | 行为 |
| --- | --- |
| 会话打开且任务运行 | 长连接接收进度，UI 实时更新 |
| 用户切换到其他会话 | 原会话任务继续，完成后写回原会话并发送对应通知 |
| 用户发送无关消息 | 正常回答，不阻塞普通聊天 |
| 用户发送相关消息 | 读取原任务状态，不重复创建命令 |
| 当前回答尚未结束时任务完成 | 先完成当前回答，再按顺序接回原 AgentRun |

### 3.2 App 退后台、退出页面、息屏

- 前台服务继续运行。
- SSH Transport 和任务监听继续运行。
- VPS 命令继续执行。
- 任务完成、失败、需要审批或连接异常时更新通知。
- 不因为生命周期变化写入 `USER_STOP`。

### 3.3 App 进程被系统回收

- VPS 任务继续执行。
- Android 进程死亡瞬间无法写入事件，因此使用服务心跳、任务租约和数据库状态判断原因。
- 进程未被用户主动停止且设备仍在运行时，前台服务使用可恢复策略自动重启。
- 自动重启后按 `execution_id` 恢复监听，并向 AgentRun 注入 `APP_INTERRUPTED` 或 `SYSTEM_RECOVERED` 事件。
- AI 必须知道手机端曾中断监听，先查询原任务，不得重复创建命令。

### 3.4 用户在系统设置中强制停止 App

- VPS 任务继续执行。
- 手机监听停止。
- 不发送远端取消命令。
- 用户重新打开 App 后恢复全部活动任务。
- AgentRun 收到“App 被强制停止后重新恢复”的事件。

### 3.5 手机重启

- 开机后不自动建立 SSH 连接。
- VPS 任务继续执行。
- 用户打开 App 后，恢复全部活动任务并补发完成结果。

### 3.6 App 卸载或清除数据

- 删除手机本地服务器记录、凭据、监听状态和本地缓存。
- 不删除 VPS 上的任务、Workspace、容器、网站、文件和服务。
- 卸载期间没有手机监听和通知。
- 用户重新安装并添加服务器后，VPS 上的任务和文件仍存在。因为本方案不上传本地数据库和密钥，原会话、原 AgentRun 与任务映射已经随 App 数据一同删除，当前版本不能自动接回原聊天。

## 四、前台服务与通知

### 4.1 服务职责

现有 `ComputerConnectionService` 继续作为基础，改造成真正的执行监听服务，负责：

1. 持有每台 VPS 的 SSH Transport。
2. 管理多个任务 Channel。
3. 接收进度、状态事件和最终结果。
4. 断线重连。
5. 把事件写入 Room 和 AgentRun。
6. 更新通知。
7. 在没有活动任务时自动退出。

服务不能因为某个页面关闭、某个 ViewModel 释放或某条普通命令结束而停止。只有所有活动任务都进入终态后，服务才自动退出。

### 4.2 通知权限

通知权限是 Agent 的使用前提：

- 没有 `POST_NOTIFICATIONS` 权限，不能开启 Agent。
- 通知渠道被系统关闭，也视为未授权。
- 没有通知权限，不能发送带 Agent 的消息。
- 没有通知权限，不能自动恢复 AgentRun。
- 普通聊天不受影响。
- 用户在任务运行期间撤销权限时，禁止创建新任务；已有 VPS 任务继续运行，服务继续监听。
- 已有任务的状态和结果可以继续监听、落库；原 AgentRun 的模型续写等待权限恢复。
- 权限恢复后，继续开放 Agent，并处理已经保存的任务结果。

### 4.3 通知内容

- 保留一条总的前台服务通知，显示当前运行中的任务数量或简短状态。
- 每个任务在完成、失败、需要确认、连接恢复或确认无法恢复时发送一条事件通知。
- 通知不提供停止、取消、通过或拒绝按钮。
- 点击通知只负责进入对应会话。
- 权限操作回到会话后，通过输入框上方现有权限卡片完成。
- 通知禁止显示命令、完整日志、文件路径、密钥、Token、密码和环境变量。

### 4.4 通知频率

只发送关键状态变化：

1. 第一次连接断开。
2. 连接恢复。
3. 任务完成。
4. 任务失败或被外部终止。
5. 需要用户确认。
6. 确认无法恢复的配置错误。

自动重试期间不重复刷通知。

## 五、连接断开与重连

### 5.1 自动重连

- 任务保持运行状态。
- 服务自动重连 SSH。
- 重连间隔逐步增加，最长约 1 分钟一次。
- 连接恢复后查询远端状态并继续接收进度。
- 重连不重新创建命令，不生成新的 `execution_id`。
- 网络不可达、VPS 暂时关机等情况持续重试。

### 5.2 不可自动恢复的错误

以下情况暂停自动重试，等待用户修复：

- 密码或私钥错误。
- Host Key 发生变化。
- SSH 用户被禁止登录。
- 服务器记录已被删除，手机没有凭据。
- Workspace 或状态目录无法访问。
- Runtime Wrapper 或 Helper 版本不兼容。

### 5.3 传给 AI 的连接事件

| 事件 | AI 应知道的内容 | AI 行为 |
| --- | --- | --- |
| `CONNECTION_LOST` | SSH 断开，VPS 任务仍可能运行，手机正在重连 | 告诉用户当前情况，不重建命令 |
| `RECONNECTED` | 连接恢复，已重新接管原任务 | 继续处理原 AgentRun |
| `CONFIG_ERROR` | 密码、Host Key 或权限配置有问题 | 告诉用户需要修复的具体原因 |
| `REMOTE_TASK_MISSING` | VPS 找不到原任务 | 告诉用户任务可能被外部删除，不自动重试 |
| `REMOTE_PROCESS_TERMINATED` | VPS 进程被外部停止 | 告诉用户任务未按 EveryTalk 的停止按钮结束 |
| `VPS_RESTARTED` | VPS 重启导致远端进程消失 | 标记远端中断，不自动重跑 |

后台期间先保存事件，用户回到会话后补充说明。重复重连不重复生成 AI 消息。

## 六、任务和 AgentRun 交互

### 6.1 用户发送新消息

同一会话存在未完成任务时，AI 根据用户消息内容判断：

- 与任务相关：读取已有任务状态，必要时读取日志，不创建第二条命令。
- 与任务无关：正常回答。
- 用户只问“好了没”：查询一次并回答当前状态，任务继续等待。
- 原任务完成后，原 AgentRun 自动接回。

### 6.2 任务完成时的消息顺序

- 用户正在进行无关对话时，后台任务完成事件先写入内部状态和通知。
- 当前这轮回答结束后，再按完成时间顺序接回原 AgentRun。
- 同一会话多个任务同时完成时，按完成时间逐个接回。
- 通知合并为摘要，避免多条消息打乱用户阅读顺序。

### 6.3 模型续写失败

- VPS 最终结果先落库。
- 不重跑远端命令。
- 模型续写失败时显示“任务已完成，正在生成回复”。
- 网络恢复或 App 下次启动后重试续写。
- 重试使用原 AgentRun 和模型快照。

### 6.4 上下文控制

- 活动任务以 `ComputerSessionState` 注入每轮模型请求。
- 状态摘要进入上下文，完整日志按需读取。
- 长日志不能完整重复注入每一轮模型请求。
- Tool Result 至少包含 `execution_id`、目标、状态、耗时、退出码、摘要和日志读取入口。
- 任务最终结果和 Agent 续写状态分别保存，防止上下文重建时重复执行。

## 七、停止语义

### 7.1 输入框“停止”

输入框的停止按钮只表达一个动作：取消当前会话当前 AgentRun。

点击后：

1. 停止模型继续生成。
2. 取消这个 AgentRun 创建的全部 VPS 任务，包含前台任务和已经转后台的任务。
3. 先保存 `USER_STOP`，再发送远端取消请求。
4. 远端确认后更新每条 Execution 的最终状态。
5. 监听这些任务的 Channel 随后关闭。
6. 其他会话、其他 AgentRun 和其他 VPS 任务不受影响。

当前不实现暂停和恢复。停止按取消处理。

### 7.2 取消与完成竞争

停止和远端完成同时发生时，以 VPS 返回的终态为准：

- VPS 先完成：保留完成结果。
- VPS 先确认取消：标记为已取消。
- Android 不依据本地点击时间覆盖远端终态。
- AI 收到最终状态后，告诉用户任务到底完成还是取消。

### 7.3 自动生命周期变化

以下情况不触发 `USER_STOP`，也不发送取消命令：

- 退出当前会话。
- 切换页面。
- 退出 App。
- 息屏。
- App 进程被系统回收。
- 系统设置强制停止 App。
- 手机重启。

## 八、权限审批

- 高风险命令在执行前暂停。
- App 在后台时，通知提示“需要你的确认”。
- 不在通知上直接通过或拒绝。
- 用户回到对应会话后，使用输入框上方现有权限卡片处理。
- 不设置 10 分钟自动失效。
- 用户拒绝后把拒绝事件传给 AgentRun，AI 结束当前步骤。
- 审批等待期间不执行危险命令。

## 九、服务器和 Workspace 生命周期

### 9.1 删除服务器配置

- 删除本地服务器记录、凭据和本地连接状态。
- 不删除 VPS 上的任务、Workspace、容器、网站、文件和服务。
- 删除时若有活动任务，提示用户任务仍会继续运行。
- 手机停止监听这些任务。
- 只删除服务器配置后，本地 Execution 记录会随服务器记录删除。当前版本重新添加服务器不会自动导入 VPS 上的旧 Execution；VPS 任务和数据不会被删除。

### 9.2 删除会话

一个 Workspace 只绑定一个会话。删除会话时：

- 删除该会话绑定的 EveryTalk Workspace。
- 删除 Workspace 目录、容器和执行记录。
- 删除前提示 Workspace 中是否还有运行中的任务。
- 用户确认后取消这些任务。
- 远端任务确认终止后再清理 Workspace。
- 取消失败时保留 Workspace，避免删除任务正在使用的文件。
- 服务器配置保留。
- 其他会话的 Workspace 保留。
- VPS 其他目录中的网站、文件和服务不受影响。

当前不增加 Workspace 锁、排队和占用提示。一个 Workspace 不会被两个会话共享。

## 十、后台监听范围

前台服务启动后恢复所有未进入终态的任务，不限当前会话：

- 多个会话可以同时运行。
- 多台 VPS 可以同时监听。
- 每条任务保留自己的 `conversation_id`、Workspace 关联和 `execution_id`。
- 点击任务通知进入对应会话。
- 已完成、失败、取消的任务不再建立监听。

## 十一、状态和事件模型

### 11.1 AgentRun 需要记录的原因

至少支持以下原因或等价字段：

| 标识 | 含义 |
| --- | --- |
| `USER_STOP` | 用户主动点击输入框停止 |
| `APP_INTERRUPTED` | App 进程被系统回收或崩溃 |
| `FORCE_STOP_RECOVERED` | 用户在系统设置强制停止后重新打开 |
| `SYSTEM_RECOVERED` | 前台服务自动恢复监听 |
| `CONNECTION_LOST` | SSH 连接断开 |
| `RECONNECTED` | SSH 连接重新建立 |
| `PERMISSION_WAITING` | 等待用户审批 |
| `MODEL_CONTINUATION_PENDING` | VPS 已完成，等待模型续写 |
| `VPS_RESTARTED` | VPS 重启导致远端进程中断 |

### 11.2 ComputerExecution 需要保留的事实

- `execution_id`
- `conversation_id` 或可反查的 Workspace 关联
- `AgentRun` 关联
- `target`
- `completionMode`
- `remoteProcessId`
- `remoteStatePath`
- `remoteStatus`
- `remoteExitCode`
- `lastObservedAt`
- 最近事件时间和日志游标
- 取消请求时间和取消结果
- 结果是否已经接回 AgentRun

字段名称以现有实体为准，实施时禁止重复新增同义字段。

### 11.3 幂等要求

- 同一 `execution_id` 只能有一个远端任务。
- 同一 `execution_id` 只能写入一个终态结果。
- 同一完成事件只能接回一次 AgentRun。
- SSH 重连、App 重启、服务重启都不能创建第二条命令。
- 未知状态不能盲目重放写操作，必须进入人工确认或继续查询。

## 十二、VPS Runtime 改造

以现有 Runtime v6 状态协议为基础，补充后台监听协议，版本号和命令名以实施阶段最终冻结为准。

必须具备：

1. 按 `execution_id` 查询状态。
2. 按 `execution_id` 读取新增日志片段。
3. 发送结构化状态事件。
4. 发送最终结果和退出码。
5. 取消时校验 `request_hash`、PID、start_ticks、进程组、运行用户和状态文件归属。
6. VPS 重启后能区分任务完成、任务缺失、进程消失和状态损坏。
7. 状态文件保存目标、请求哈希、开始时间、更新时间、PID、start_ticks、退出码和日志游标。
8. 后台任务不套 Android 的前台命令超时。

## 十五、验收清单

### 15.1 长任务

- [ ] 启动一个超过 10 分钟的后台任务，退出会话后任务继续。
- [ ] 息屏期间 VPS 进程继续运行。
- [ ] App 回到前台后能看到实时或最近一次进度。
- [ ] 任务完成后通知到达，进入会话后自动生成 AI 回复。

### 15.2 断线和恢复

- [ ] 断开网络，通知只出现一次“连接断开”。
- [ ] 恢复网络后出现一次“连接恢复”。
- [ ] 恢复过程中不创建第二条 VPS 命令。
- [ ] 杀掉 App 进程后，重新打开能按 `execution_id` 接回。
- [ ] 系统设置强制停止后重新打开能接回。
- [ ] 手机重启后打开 App 能接回，开机期间不主动连接。

### 15.3 停止

- [ ] 输入框点击停止会取消当前 AgentRun 的前台和后台任务。
- [ ] 其他会话任务继续运行。
- [ ] 任务完成与停止竞争时，以 VPS 终态为准。
- [ ] 离开 App、息屏和系统回收不会写入 `USER_STOP`。

### 15.4 通知和权限

- [ ] 关闭通知权限后无法开启或恢复 Agent。
- [ ] 已有任务在权限被撤销后继续运行。
- [ ] 通知没有操作按钮。
- [ ] 通知不泄露命令和敏感输出。
- [ ] 权限审批从会话权限卡片完成。

### 15.5 删除边界

- [ ] 删除服务器配置不删除 VPS 网站、文件、容器和任务。
- [ ] 删除会话会提示活动任务。
- [ ] 确认后先取消任务，再删除对应 Workspace。
- [ ] 取消失败时 Workspace 保留。
- [ ] 一个 Workspace 始终只对应一个会话。

- 不新增 EveryTalk 云端控制面。
